# WireGuard + wg-easy + Telegram: установка с нуля

Полная инструкция для **Ubuntu Server 24.04 LTS**: подготовка VPS → Docker →
wg-easy → подключение телефона → Telegram-бот → обновление и диагностика.

Бот создаёт VPN-клиентов, отправляет `.conf` и QR-коды, показывает устройства,
включает и отключает доступ, удаляет клиентов с подтверждением и показывает
текущие счётчики трафика. Управление доступно только администратору в личном чате.
Пересылка конфигов разрешена по умолчанию.

> Если wg-easy уже работает, перейдите к разделу **7. Telegram-бот**.
> Если и бот уже установлен, используйте раздел **10. Обновление**.
> Установщик этого проекта устанавливает бота. Docker и wg-easy устанавливаются
> отдельными командами ниже. Полная переустановка существующего VPS не требуется.

## 1. Сервер и необходимые данные

В панели своего VPS-провайдера создайте виртуальный сервер с образом
**Ubuntu Server 24.04 LTS, amd64 или arm64**. Нужны публичный IP, SSH-доступ
и поддержка WireGuard в ядре. Для обычного VPS подходит стандартное ядро Ubuntu;
в ограниченных контейнерных VPS доступность WireGuard уточняйте у провайдера.

Установку ОС выполняет панель провайдера. На уже используемом сервере
с ботами, сайтами или данными **не нажимайте переустановку ОС**.

Подготовьте:

| Данные | Где взять |
| --- | --- |
| Публичный IP сервера | Панель VPS-провайдера |
| SSH-пользователь и пароль или ключ | Панель провайдера |
| Логин и пароль wg-easy | Создадите при первом входе в панель |
| Токен Telegram-бота | @BotFather, команда `/newbot` |
| Числовой Telegram ID администратора | Например, @userinfobot |

Домен для описанного способа не нужен. В примерах `IP_СЕРВЕРА` нужно заменить
реальным публичным адресом VPS; угловые скобки добавлять не нужно.

## 2. Подключение и подготовка Ubuntu

**На компьютере**, в PowerShell Windows, Terminal macOS или Linux:

```powershell
ssh root@IP_СЕРВЕРА
```

При первом подключении сверьте отпечаток ключа SSH с данными провайдера.
Введите пароль: символы при вводе не отображаются. Если провайдер выдал
пользователя `ubuntu`, подключайтесь как `ssh ubuntu@IP_СЕРВЕРА`, а затем
выполните `sudo -i`.

**Дальнейшие Linux-команды выполняются на сервере от root**, если явно
не указано «на компьютере».

Проверьте ОС и установите базовые инструменты:

```bash
cat /etc/os-release
uname -m
apt update
apt install -y ca-certificates curl nano python3
```

Ожидается Ubuntu 24.04 и архитектура `x86_64` или `aarch64`.
Обычные обновления системы можно установить через `apt upgrade`; если после
обновления ядра потребуется перезагрузка, выполните её в удобное время и
подключитесь по SSH заново. На рабочем сервере учитывайте другие службы.

## 3. Установка Docker

Сначала проверьте, не установлен ли Docker:

```bash
docker --version
docker compose version
```

Если обе команды работают, переходите к проверке `hello-world` ниже.
Следующий блок предназначен для чистой Ubuntu 24.04 без Docker.
Если уже установлены пакеты `docker.io`, `podman-docker` или отдельный
`containerd`, сначала ознакомьтесь с разделом о конфликтующих пакетах
в [официальной инструкции Docker](https://docs.docker.com/engine/install/ubuntu/).

Добавьте официальный репозиторий и установите Docker Compose:

```bash
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc

cat > /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: noble
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
systemctl enable --now docker
```

Не добавляйте второй источник Docker, если он уже прописан в `docker.list`
или `docker.sources`.

Проверка:

```bash
docker run --rm hello-world
docker compose version
systemctl is-active docker
```

Ожидается `Hello from Docker!`, версия Compose и `active`.

## 4. Сетевой экран и порты

В сетевом экране **панели VPS-провайдера** разрешите:

| Порт | Назначение | Кому доступен |
| --- | --- | --- |
| TCP 22 или ваш SSH-порт | Подключение и SSH-туннель | Вашему IP, если он постоянный |
| UDP 51820 | WireGuard VPN | Устройствам, подключающимся к VPN |
| TCP 51821 | Веб-панель | Только localhost на сервере; наружу не открывать |

Для бота не нужны входящие HTTP-порты: он получает обновления Telegram
через исходящие HTTPS-запросы. Серверу нужны исходящий DNS и HTTPS для
Ubuntu, Docker Registry, GitHub, PyPI и Telegram.

Проверьте UFW:

```bash
ufw status
```

Если UFW выключен, для этой инструкции его включать не требуется.
Если включён, добавьте разрешение для WireGuard:

```bash
ufw allow 51820/udp
```

Не меняйте SSH-правила и не включайте UFW до разрешения вашего SSH-порта.
Docker может обходить обычные правила UFW для опубликованных контейнерных
портов. Поэтому панель ниже привязывается именно к `127.0.0.1`, а доступ
к VPN дополнительно регулируется сетевым экраном провайдера.

## 5. Установка wg-easy

Этот раздел — для новой установки. Если `/opt/wg-easy` уже существует
и VPN работает, не перезаписывайте его конфигурацию.

Создайте файл Compose:

```bash
mkdir -p /opt/wg-easy
cd /opt/wg-easy

cat > docker-compose.yml <<'YAML'
volumes:
  etc_wireguard:

services:
  wg-easy:
    image: ghcr.io/wg-easy/wg-easy:15
    container_name: wg-easy
    environment:
      INSECURE: "true"
    networks:
      wg:
        ipv4_address: 10.42.42.42
        ipv6_address: fdcc:ad94:bacf:61a3::2a
    volumes:
      - etc_wireguard:/etc/wireguard
      - /lib/modules:/lib/modules:ro
    ports:
      - "51820:51820/udp"
      - "127.0.0.1:51821:51821/tcp"
    restart: unless-stopped
    cap_add:
      - NET_ADMIN
      - SYS_MODULE
    sysctls:
      - net.ipv4.ip_forward=1
      - net.ipv4.conf.all.src_valid_mark=1
      - net.ipv6.conf.all.disable_ipv6=0
      - net.ipv6.conf.all.forwarding=1
      - net.ipv6.conf.default.forwarding=1

networks:
  wg:
    driver: bridge
    enable_ipv6: true
    ipam:
      driver: default
      config:
        - subnet: 10.42.42.0/24
        - subnet: fdcc:ad94:bacf:61a3::/64
YAML

docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail=50
```

Первое скачивание образа может занять несколько минут. Сразу после старта
`health: starting` нормально; позднее ожидается `healthy`.
В выводе портов панели должно быть **`127.0.0.1:51821`**, а не `0.0.0.0:51821`.

Compose основан на [официальной конфигурации wg-easy](https://github.com/wg-easy/wg-easy/blob/master/docker-compose.yml).
HTTP разрешён только для локального соединения; удалённый доступ идёт
внутри зашифрованного SSH-туннеля. Настройки и ключи сохраняются в томе
`wg-easy_etc_wireguard`. Не выполняйте `docker compose down -v`: это удаляет
том с данными. Если указанные подсети уже заняты другими сетями на VPS,
выберите свободные до запуска и согласованно замените подсеть и адрес контейнера.

## 6. Настройка панели и проверка VPN

### Откройте SSH-туннель

**На компьютере откройте второе окно PowerShell или терминала:**

```powershell
ssh -N -L 51821:127.0.0.1:51821 root@IP_СЕРВЕРА
```

При другом SSH-пользователе замените `root`. Для нестандартного SSH-порта
добавьте `-p ВАШ_ПОРТ`. Введите SSH-пароль и оставьте окно открытым.
После входа отсутствие текста нормально. При закрытии окна доступ к панели
через этот туннель прекратится; сам VPN и бот продолжат работать.

Откройте **на том же компьютере** [http://localhost:51821](http://localhost:51821).
Если настраиваете с телефона, используйте SSH-клиент с локальным пробросом
порта: локальный `51821` → `127.0.0.1:51821` на VPS. Просто открывать
`localhost` на другом устройстве без туннеля недостаточно.

### Пройдите мастер wg-easy

1. Создайте логин и надёжный пароль администратора панели. Это отдельные
   данные, они не обязаны совпадать с SSH-пользователем и паролем.
2. В адресе VPN-сервера укажите **публичный IP VPS**, не `localhost` и не
   `10.42.42.42`.
3. Порт WireGuard оставьте `51820`.
4. Завершите мастер; остальные значения оставьте по умолчанию, если нет
   специальных требований к DNS или маршрутизации.
5. Сохраните логин и пароль — они понадобятся боту для API.

Бот использует Basic Auth API wg-easy. По [документации API](https://wg-easy.github.io/wg-easy/latest/advanced/api/)
этот способ не работает с включённой 2FA. Описанная конфигурация рассчитана
на локальную панель и Basic Auth без 2FA. Если хотите сохранить 2FA,
потребуется другой способ интеграции; текущий бот его не реализует.

### Подключите первое устройство

1. В панели создайте клиента, например `Телефон`.
2. Установите приложение [WireGuard](https://www.wireguard.com/install/).
3. Добавьте туннель сканированием QR-кода. Если панель на том же телефоне,
   скачайте `.conf` и импортируйте файл в WireGuard.
4. Включите туннель и проверьте открытие сайтов и внешний IP.
5. При полном туннеле внешний IPv4 должен стать публичным IPv4 VPS.

Если VPN не работает, сначала исправьте его по разделу диагностики.
Бот управляет клиентами, но не исправляет сетевые настройки WireGuard.
Каждому устройству создавайте отдельного клиента.

## 7. Telegram-бот

### Создайте бота и получите свой ID

1. Откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Укажите название и свободный username, заканчивающийся на `bot`.
3. Сохраните выданный токен. Его нужно вводить только на сервере.
4. Узнайте свой **числовой** Telegram ID, например через
   [@userinfobot](https://t.me/userinfobot). Username с `@` вместо ID не подходит.

Токен и пароль панели не публикуйте в репозитории, переписке или скриншотах.

### Запустите установщик на сервере

```bash
curl -fL https://raw.githubusercontent.com/ECL1SSI/wg-telegram/main/setup-wg-telegram.sh -o /tmp/setup-wg-telegram.sh
bash /tmp/setup-wg-telegram.sh
```

Установщик запросит недостающие значения:

| Запрос | Что вводить |
| --- | --- |
| Токен от BotFather | Полный токен нового бота |
| Твой числовой Telegram ID | ID вашего личного аккаунта |
| Логин веб-панели wg-easy | Созданный в мастере логин панели |
| Пароль веб-панели wg-easy | Пароль панели, не пароль SSH |

Токен и пароль при вводе не отображаются. Каждое значение вводится отдельным
ответом с Enter. Существующий `/opt/wg-telegram/.env` используется повторно;
заполненные поля заново не запрашиваются.

Установщик установит Python-зависимости в venv, проверит `/api/client`
и токен Telegram, создаст пользователя `wg-telegram` и службу systemd.
Бот не получает права root и доступ к Docker. Установщик не меняет VPN-клиентов,
Docker, правила firewall и конфигурацию wg-easy.

Проверьте запуск:

```bash
systemctl status wg-telegram --no-pager -l
journalctl -u wg-telegram -n 30 --no-pager -o cat
```

Ожидается `active (running)` и сообщение «Бот запущен; API wg-easy доступен».
Откройте своего бота в Telegram и отправьте **`/start`**.

## 8. Как пользоваться ботом

| Кнопка | Действие |
| --- | --- |
| ➕ Создать подключение | Введите имя; бот создаст клиента и пришлёт `.conf` и QR |
| 📋 Подключения | Все клиенты wg-easy, включая созданных через панель |
| 📄 Конфиг + QR | Повторно получить конфигурацию выбранного устройства |
| ⏸ Отключить / ▶️ Включить | Приостановить или восстановить доступ клиента |
| 🗑 Удалить | Удалить клиента после отдельного подтверждения |
| 📊 Статистика | Число устройств и текущие счётчики трафика |

Команды `/start` и `/menu` открывают меню; `/cancel` отменяет ввод имени.
Подтверждение удаления одноразовое и действует 2 минуты.
Доступ разрешён только ID из `.env` в личном чате. В группах управление
запрещено, даже если кнопку нажимает администратор.

Для друга создайте отдельного клиента и перешлите его `.conf` или QR.
Передавать доступ к самому боту для этого не требуется.
Любой получатель конфига получает доступ к VPN; не публикуйте его в общем чате.
Файлы и QR содержат приватный ключ и передаются через обычный личный чат Telegram.

## 9. Настройки и пересылка

Редактирование настроек на сервере:

```bash
nano /opt/wg-telegram/.env
```

Пример структуры — **не заменяйте рабочие секреты этим примером**:

```dotenv
TELEGRAM_BOT_TOKEN=ТОКЕН_ОТ_BOTFATHER
TELEGRAM_ADMIN_ID=ЧИСЛОВОЙ_ID
WG_EASY_URL=http://127.0.0.1:51821
WG_EASY_USERNAME=ЛОГИН_ПАНЕЛИ
WG_EASY_PASSWORD="ПАРОЛЬ_ПАНЕЛИ"
PROTECT_CONTENT=false
```

Установщик сам записывает строки с нужным экранированием. При ручном
редактировании значения со специальными символами оформляйте по синтаксису
`.env`; не выполняйте `source .env`.

- `PROTECT_CONTENT=false` — разрешить пересылку конфигов и QR.
- `PROTECT_CONTENT=true` — включить защиту новых сообщений от пересылки.
- `WG_EASY_URL` — локальная HTTP-панель на этом сервере; удалённые URL бот
  намеренно не принимает.

После изменений:

```bash
systemctl restart wg-telegram
```

Для изменения защиты файлов заново нажмите **«Конфиг + QR»**.
Старые сообщения сохраняют прежнюю настройку пересылки.
Файл `.env` читается ботом напрямую; в Git он не загружается.

## 10. Обновление

### Telegram-бот

Повторите команды установки:

```bash
curl -fL https://raw.githubusercontent.com/ECL1SSI/wg-telegram/main/setup-wg-telegram.sh -o /tmp/setup-wg-telegram.sh
bash /tmp/setup-wg-telegram.sh
```

Настройки `.env` сохраняются; предыдущие файлы кода копируются в
`*.backup-<timestamp>`. После установки отправьте `/start` и проверьте
список клиентов. Это обновление бота, а не wg-easy.

### wg-easy в пределах версии 15

Перед обновлением сохраните резервную копию конфигурации и данных wg-easy
средствами вашего VPS или отдельным согласованным бэкапом Docker-тома.
Затем:

```bash
cd /opt/wg-easy
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=50
```

Образ `:15` получает обновления в рамках этой основной версии.
API wg-easy нестабилен и может измениться. В этой установке подтверждена
авторизация и получение списка клиентов на **15.4.0**; живые операции
создания, скачивания и удаления нужно проверить после установки бота.
Не переходите на новую основную версию без проверки совместимости.
Не используйте `docker compose down -v` и не удаляйте том с ключами.

## 11. Диагностика

### Панель не открывается

1. Проверьте, что SSH-туннель открыт на том же устройстве, где запущен браузер.
2. Откройте `http://localhost:51821`, не публичный IP с портом 51821.
3. Проверьте сервер:

```bash
cd /opt/wg-easy
docker compose ps
docker compose logs --tail=80
curl -I http://127.0.0.1:51821
```

Если локальный порт компьютера занят, создайте туннель
`ssh -N -L 51822:127.0.0.1:51821 root@IP_СЕРВЕРА` и откройте
`http://localhost:51822`.

### VPN подключён, но сайты не работают

Проверьте публичный IP в настройках wg-easy, UDP 51820 у провайдера,
состояние клиента и последний handshake. На сервере:

```bash
docker exec wg-easy wg show
```

Отсутствие свежего handshake обычно указывает на недоступность UDP-порта,
неверный адрес/порт или конфиг. При наличии handshake проверьте DNS,
маршрутизацию и серверные логи. После изменения адреса сервера получите
актуальный конфиг и заново импортируйте его на устройство.

### Бот не отвечает

```bash
systemctl status wg-telegram --no-pager -l
journalctl -u wg-telegram -n 80 --no-pager -o cat
```

Проверьте числовой `TELEGRAM_ADMIN_ID`, личный чат и исходящий доступ
сервера к `api.telegram.org`. Один токен должен использоваться одной
запущенной копией бота. Установщик использует long polling, HTTPS webhook
ему не нужен.

### HTTP 401 от wg-easy

Проверьте повторный вход в веб-панель с теми же данными и настройки
`WG_EASY_USERNAME` / `WG_EASY_PASSWORD`. Нужен логин панели, не `root`.
Учтите ограничение 2FA для Basic Auth API. После исправления `.env`
перезапустите `wg-telegram`.

### Ошибка при создании или отправке конфигурации

После тайм-аута сначала проверьте список: клиент мог успеть создаться.
Повторную выдачу файла выполните через «Конфиг + QR». Автоматические
повторы создания отключены. Обновления Telegram отмечаются обработанными
до изменения VPN, чтобы избежать повторного создания после сбоя; при аварии
ответ может потеряться — тогда проверьте список.

### Управление службами

```bash
systemctl restart wg-telegram
systemctl stop wg-telegram
systemctl start wg-telegram
systemctl is-enabled wg-telegram
```

Docker и бот запускаются через systemd. Контейнер wg-easy имеет
`restart: unless-stopped`; если его остановили вручную, запустите
`cd /opt/wg-easy` и `docker compose up -d`.
Трафик в боте — текущие счётчики WireGuard, не постоянная помесячная статистика;
после перезапуска интерфейса они могут обнулиться.

## 12. Проверка и сборка проекта

Исходники Python запускаются из venv. Компиляция в отдельный бинарник
для установки на Ubuntu не нужна.

В скачанном или клонированном проекте:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m compileall -q bot.py configure.py build.py
bash -n install.sh
python3 build.py
bash -n dist/setup-wg-telegram.sh
```

В `dist/` появятся один установщик и архив исходников. При наличии исходников
на VPS можно установить бота командой `sudo bash install.sh`.

GitHub Actions автоматически запускает проверки и сохраняет пакет
`wg-telegram-installers` в [разделе Actions](https://github.com/ECL1SSI/wg-telegram/actions).
Откройте успешный запуск **Check and package**, затем скачайте артефакт
внизу страницы. Для скачивания артефакта может потребоваться вход в GitHub.

Модульные проверки используют заглушки API. Токены, `.env`, конфиги, изображения
и venv исключены из Git. Пакет содержит бот и установщик, а не исходники wg-easy.
